# Clarifying questions for the timesheet user story

Generated by an LLM (Activity 1) using the What / Where / Why / When / Who / How heuristic,
focused on **Accuracy** and **Consistency**. Each question is tagged with one of:
**[Do now]**, **[Keep for later]**, **[Drop]**.

---

**[Do now]** What happens when time is entered that is not a multiple of half an hour?
The story says time is tracked in half hour units, but it does not say whether 0.25 h or 1.7 h is rejected, rounded up, rounded down, or rounded to the nearest half hour. (Accuracy)

**[Do now]** How will the system handle invalid time entries such as zero, negative or non-numeric values?
"An amount of time must be entered" implies validation, but the story does not define what counts as an invalid amount or how the user is told about it. (Accuracy)

**[Do now]** What happens when the same user tracks time against the same project more than once?
Should the entries be kept as separate records, or should the hours be added to a running total for that project? This decides whether a project can appear once or many times in the history. (Consistency)

**[Do now]** How is a project identified, and is the project name case- and whitespace-sensitive?
If "Project A" and "project a " are treated as different projects, totals will be split inconsistently across what the user thinks is one project. (Consistency)

**[Do now]** What should happen if a timesheet is submitted with a missing or empty project name?
"A project and amount of time must be entered" says both are required, but the expected behaviour (reject, error, default project) is not stated. (Accuracy)

**[Keep for later]** Where does the list of valid projects come from, and must a project exist before time can be tracked against it?
Without a reference list, typos create new projects silently and the history becomes inconsistent. (Consistency)

**[Keep for later]** Who is "I", and how is ownership of tracked time enforced?
"Only I should be able to see my tracked time" implies authentication and per-user data, but there is a single user in this exercise and no login. (Consistency)

**[Keep for later]** Is there a maximum amount of time that can be tracked per entry or per day (e.g. more than 24 hours)?
Very large values may be accurate from the system's point of view but inaccurate from a business point of view. (Accuracy)

**[Keep for later]** Can a submitted timesheet be edited or deleted afterwards, and how does that affect the recorded history?
The story asks for a history, but does not say whether it is append-only or correctable. (Consistency)

**[Drop]** When is the time recorded, and which time zone is used for the entry date?
The story only records *how much* time was spent, not *when* it was spent, so dates and time zones are out of scope. (Accuracy)
